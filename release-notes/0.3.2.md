- **Repairs links left behind by course renames.** *Rename a course* in versions before 0.3.1 could leave the course note's own lecture list pointing at the old folder name (for example `[[School/Fall 2026 ALGORITHMS (…)/2026-09-01]]` after renaming the course to `Algorithms`). On first start, 0.3.2 repairs those once: in notes inside a course or meeting folder, a broken link to `<course folder>/<old folder name>/<name>` is pointed at the note's own course folder when `<name>` exists there. Only links that are broken are touched, every note it edits is backed up first (in the plugin's `backups` folder), and a notice says how many were repaired. Links in notes outside course folders are left alone, because a lecture's name (its date) can exist in several courses.
- New command **Repair links that still point at a course's old folder name** runs the same repair again, for example after renaming a course folder by hand.
- The end-to-end tests check that, after a rename, the course note's own lecture links resolve, and cover the repair (6/6 passing in a real Obsidian, with *Automatically update internal links* both off and on).
